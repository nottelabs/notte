---
title: "SecretProxy"
description: "Your own TLS-intercepting proxy that swaps stand-in values for secrets"
---



Traffic to `hosts` is routed through this proxy, which decrypts it, replaces the stand-in
values typed in the browser with the real secrets, and opens its own connection to the
destination. The proxy must forward that traffic to an exit itself. All other traffic uses
the session's other proxy entry (or a direct connection when there is none).

Leave `server` unset to use the workspace's saved secret proxy: the fields you set then
replace the saved ones for this session.

At most one `secret` entry is allowed per session, and it cannot be combined with a
`tailnet` entry

## Fields

<ParamField path="type" type="Literal['secret']" default="secret">
</ParamField>

<ParamField path="server" type="str | None">
  The secret proxy, as http://host:port or https://host:port on a public address. Leave it unset to use the workspace's saved secret proxy.
</ParamField>

<ParamField path="username" type="str | None">
  Basic auth username for the secret proxy.
</ParamField>

<ParamField path="password" type="str | None">
  Basic auth password for the secret proxy. Never stored or returned.
</ParamField>

<ParamField path="ca_certificate" type="str | None">
  PEM CA certificates the browser trusts for this session: for the secret proxy itself and for the certificates it presents for `hosts`. At most 16384 bytes; each must be a CA and not expired. Never include a private key.
</ParamField>

<ParamField path="hosts" type="list[str] | None">
  Hosts routed through the secret proxy: exact hostnames or a leading '*.' wildcard, without scheme, path or port. A bare '*' is not allowed. Required with `server`.
</ParamField>
