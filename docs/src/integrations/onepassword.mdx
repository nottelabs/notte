There are two ways to use 1Password with Notte:

| Option | How it works | Use it when |
|---|---|---|
| [Connect 1Password](#connect-1password) | You connect your 1Password account in the Notte console and approve each login in the 1Password app. The 1Password extension fills and submits the login form inside the Notte browser. Notte never sees the password. | A person owns the logins and can approve them |
| [Service account](#read-secrets-with-a-service-account) | Your code reads fields from a vault with the [1Password SDK](https://www.1password.dev/sdks), using a service account token. | Unattended or scheduled automations, such as [Functions](/concepts/functions) |

## Connect 1Password

<Note>
  This integration is in preview with 1Password. It currently needs a US 1Password Individual or Families account and the 1Password desktop app on the Nightly channel.
</Note>

### How it works

1. **Connect once.** In the [Notte console](https://console.notte.cc), open **Settings > Integrations**, choose **1Password** and click **Connect 1Password**. You sign in to 1Password, pick the account and approve Notte. The connection belongs to you, the Notte user who connected it.
2. **Start a session with 1Password.** Pass `onepassword: true` when you start the session. The browser starts with the 1Password extension and stays in a sign-in phase: until you release it, no CDP client, viewer or session replay can attach, so nothing else can read the page while a login is filled.
3. **Request access.** Ask for the logins the session needs, by website. 1Password returns an approval link. Open it on the device running 1Password and choose which login to share.
4. **Fill.** Once approved, each login becomes a grant. Ask Notte to fill a grant on its login page: the 1Password extension fills the form and submits it. The password goes from 1Password to the page directly and never reaches Notte, your code or a model.
5. **Release.** When sign-in is done, release the session. Fills stop for good, every page reloads, and the session becomes a normal session your code, agents and viewers can use, signed in.

Notte stores only opaque references to the logins you granted, never their values. A grant can be reused in later sessions for 30 days without asking again. Disconnect at any time from **Settings > Integrations**; 1Password can also end the connection, in which case the console asks you to reconnect.

### Sign in a session

These routes use your [Notte API key](https://console.notte.cc/apikeys) and are called over HTTP. Set `NOTTE_API_KEY` first.

<Steps>
  <Step title="Start the session">
    <Start />

    Keep the returned `session_id`. The start fails if your 1Password connection is missing or needs a reconnect.
  </Step>

  <Step title="Request access to a login">
    <AccessRequest />

    A request lists up to 5 websites (`https://` URLs), each with an optional `reason` (100 characters) and up to 5 `keywords`, plus an optional `goal` (140 characters) that 1Password shows the person. The answer has an `id`, a `state` of `pending` and an `app_link`. Send `app_link` to the person who approves the login, on the device running 1Password. Do not pass it to an AI model.
  </Step>

  <Step title="Wait for approval">
    <Poll />

    Poll every few seconds. Notte checks with 1Password on its own schedule however often you read, so polling faster does not speed it up. When the person approves, `state` becomes `resolved` and `grants` lists one entry per shared login, each with an `id` and its `website`. Any other final state means no login was shared.
  </Step>

  <Step title="Fill the login">
    <Fill />

    `url` is the page with the login form, on the grant's website. The answer's `status` is `fill_submitted` when the form was submitted, which does not mean the site accepted the login: check the returned `url` to see where the browser landed. For a login split over several pages, call fill once per page.
  </Step>

  <Step title="Release the session">
    <Release />

    Release is final: later fills on this session are refused, so start a new session to sign in again. If a fill is still running, release answers `409`; call it again.
  </Step>

  <Step title="Use the signed-in session">
    The session is now a normal signed-in session. Attach to it as usual, for example with `client.Session(session_id)` in the Python SDK, and run your code, agent or scrape on it.
  </Step>
</Steps>

### Limits

- A 1Password session cannot be combined with `cdp_url`, `demonstrate`, `auth_ids` or a [secret proxy](/features/sessions/secret-proxies/overview), and its replay is not recorded.
- Approval needs a person with the 1Password app at least once per login. After that, the grant is reused for 30 days.
- 1Password protects the password, not the login it produces: once released, the signed-in session's cookies are available to your code like in any session.

## Read secrets with a service account

For automations that run without a person, read fields from a vault with a [1Password service account](https://start.1password.com/developer-tools/infrastructure-secrets/serviceaccount/). Give it read access to a vault that holds only the items your automation needs. Fields are addressed with [secret references](https://www.1password.dev/sdks/load-secrets) such as `op://Merchants/Portal/password`.

### In a Notte Function

The 1Password SDK (`onepassword`) is installed in the Functions runtime, so a Function can read credentials at run time:

1. Store the token as a [Function Secret](/features/functions/creating#secrets) named `OP_SERVICE_ACCOUNT_TOKEN`, in the console under **Settings > Function Secrets**. Every run receives it as an environment variable.
2. Upload the Function with the code check relaxed (`restricted=False`), since reading environment variables needs `os`.

<MerchantLogin />

Pass the secret references as run variables, never the values, and adapt the locators to your login page. Filling through Playwright keeps the values out of the session's action history. [Schedule](/features/functions/schedules) the Function to run it at the cadence you need.

### On your own machine

The [examples/onepassword](https://github.com/nottelabs/notte/tree/main/examples/onepassword) folder has Python and TypeScript versions of the same flow, filling a test form. Set `OP_SERVICE_ACCOUNT_TOKEN`, `OP_USERNAME_REF`, `OP_PASSWORD_REF` and `NOTTE_API_KEY`, then follow its README.

<Tabs>
  <Tab title="Python">
    Use Python 3.11+ and uv. Run `uv sync --locked`, then `uv run python python/demo.py`.
  </Tab>
  <Tab title="TypeScript">
    Use Node.js 24+. Open `typescript`, run `npm ci`, then `npm start`.
  </Tab>
</Tabs>

Reuse its `fill_login` or `fillLogin` helper on your page. It resolves only the two references you pass and does not print their values.
