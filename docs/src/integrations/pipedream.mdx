Use native MCP clients to connect [Notte browser tools](/mcp-server) and [Pipedream connected apps](https://pipedream.com/docs/connect/mcp/developers) in one application. The Python and TypeScript [example project](https://github.com/nottelabs/notte/tree/main/examples/pipedream) reads a page and discovers app tools without invoking vendor actions.

## Set up

Use Python 3.11+ or Node.js 24.8+, a [Notte API key](https://console.notte.cc/apikeys), and your own Pipedream [project](https://pipedream.com/projects) and [OAuth client](https://pipedream.com/settings/api).

Clone the [Notte repository](https://github.com/nottelabs/notte) and open `examples/pipedream`. Run `uv sync --locked` or `npm ci`. Set `NOTTE_API_KEY`, `PIPEDREAM_CLIENT_ID`, `PIPEDREAM_CLIENT_SECRET`, `PIPEDREAM_PROJECT_ID` and `PIPEDREAM_EXTERNAL_USER_ID`, then run `uv run --locked python demo.py` or `npm start`.

The demo reads `example.com`, lists the selected app's tools, and returns a tool count and stopped browser ID. `PIPEDREAM_APP` defaults to `github`; Pipedream requests use its development environment.

## Connections and actions

Keep credentials server-side and derive Pipedream's external user ID from your authenticated application. Pipedream manages provider connections; your Notte key only authenticates browser requests.

Tool discovery does not make every advertised action read-only. Before invoking an action elsewhere, select its actual name and schema, obtain the required human approval, and complete its connection flow. Pipedream can return a hosted Connect Link when an action needs authorization; discovery alone does not start OAuth.

The example owns a browser with a three-minute lifetime and closes it on success, failure or cancellation. It does not add a Notte OAuth UI or automatically attach connected-app tools to Notte Agent API runs.

Native protocol tests cover a real Notte browser with local Pipedream OAuth/MCP fixtures. Hosted Pipedream OAuth and vendor action execution have not been tested.
