[Evervault Browser Tokens](https://docs.evervault.com/browser-tokens) turn encrypted card data and credentials into format-preserving stand-ins for an agent to type. Evervault's browser proxy replaces each token with the real value, but only on its way to the hostnames you allow. Use it as a Notte [secret proxy](/features/sessions/secret-proxies/overview).

## Prerequisites

- An Evervault app with Browser Tokens, and its app ID and API key.
- The data to fill, encrypted with Evervault (for example with [Card Collection](https://docs.evervault.com/cards/card-collection)).
- The hostnames that receive the data: the payment provider or iframe host, not only the merchant's site.
- `curl` and `jq` for the example below.

## Map Evervault's values to the secret entry

Each `POST /browser-tokens` call returns the stand-ins (`data[].value`) and a `proxyConfiguration` for Evervault's browser proxy. Use it like this:

| Secret entry field | Value |
|--------------------|-------|
| `server` | `https://` + `proxyConfiguration.hostname` + `:` + `proxyConfiguration.port`, for example `https://us-va.browser.relay.evervault.app:443` (US) or `https://eu-ie.browser.relay.evervault.app:443` (EU) |
| `username` | `proxyConfiguration.username` |
| `password` | `proxyConfiguration.password`. Evervault issues a new, time-bound password with each batch of tokens, so send it with each session. |
| `ca_certificate` | Evervault's CA certificate, from [ca.evervault.com](https://ca.evervault.com) (PEM). |
| `hosts` | The same hostnames as the `target` values of your `permissions`. Both use the same rules: exact hostnames or a leading `*.` wildcard. |

The tokens and the proxy password stop working when the `ttl` you set expires, so set a `ttl` that covers the whole session.

If you [save the configuration in the console](/features/sessions/secret-proxies/overview#save-the-configuration-in-the-console) with the Evervault preset, save the server, username, CA certificate and hosts, and send only the `password` with each session.

## Share the exit IP

By default, requests to the listed hosts leave from Evervault's IP addresses. Evervault can send its outgoing traffic through your own CONNECT proxy with `proxySettings` of `type: "custom"`. Point it at Notte's proxy gateway with a [gateway credential](/features/sessions/secret-proxies/overview#share-the-exit-ip), and give the session's `notte` entry the same `sticky_session`. The site then sees the session's exit IP for every request.

| `proxySettings` field | Value |
|-----------------------|-------|
| `type` | `custom` |
| `scheme` | `https` |
| `hostname` | `proxy.notte.cc` |
| `port` | `443` |
| `username`, `password` | The `username` and `password` of the gateway credential |

<Note>
  Evervault accepts egress credentials of up to 256 characters. The gateway username contains your `sticky_session` twice, so keep `sticky_session` to 32 characters or fewer.
</Note>

## Mask real values in responses

Notte does not change responses, so a listed site that sends a real value back exposes it to the browser. See [Mask real values in responses](/features/sessions/secret-proxies/overview#mask-real-values-in-responses).
