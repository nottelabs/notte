Every Notte session follows a predictable lifecycle from creation to termination. Understanding this lifecycle helps you build reliable automation workflows and manage resources effectively.

## Session States

Sessions transition through these states:

* **`authenticating`** - Session was started with [Managed Auth](/features/sessions/configuration#managed-auth) connections and login is still in progress
* **`active`** - Session is running and ready to accept operations
* **`closed`** - Session has been terminated normally
* **`error`** - Session encountered an error and terminated unexpectedly
* **`timed_out`** - Session hit its idle timeout or maximum duration

## Getting Session Details

Retrieve current information about your session:

<GetSessionDetails />

<ResponseField name="session_id" type="string">
  Unique identifier for the session
</ResponseField>

<ResponseField name="status" type="string">
  Current status: `authenticating`, `active`, `closed`, `error`, or `timed_out`
</ResponseField>

<ResponseField name="created_at" type="datetime">
  Session creation timestamp
</ResponseField>

<ResponseField name="closed_at" type="datetime | None">
  Session closure timestamp (None if still active)
</ResponseField>

<ResponseField name="last_accessed_at" type="datetime">
  Last operation timestamp
</ResponseField>

<ResponseField name="idle_timeout_minutes" type="integer">
  Idle timeout in minutes. The session closes after this long without any operation.
</ResponseField>

<ResponseField name="max_duration_minutes" type="integer">
  Maximum session lifetime in minutes, regardless of activity
</ResponseField>

<ResponseField name="close_reason" type="string | None">
  Why the session closed: `manual`, `idle_timeout`, `max_duration`, `error`, or `unknown` (None while active)
</ResponseField>

<ResponseField name="duration" type="timedelta">
  Total session duration
</ResponseField>

## Best Practices

Follow these patterns to build reliable, cost-effective automation:

### 1. Always Use Context Managers

Python's `with` statement and TypeScript's `use()` callback guarantee cleanup:

<ContextManager />

### 2. Set Appropriate Timeouts

Sessions have two limits:

* **`idle_timeout_minutes`** (default 3, max 30) - closes the session after this long without any operation. Each operation resets it.
* **`max_duration_minutes`** (default 15, max 1440) - closes the session after this long, regardless of activity.

The idle timeout cannot exceed the maximum duration, so raise `max_duration_minutes` first for long workflows. Set the idle timeout to cover the longest pause between operations, for example while an agent thinks or a page loads.

Check session status before long-running operations:
