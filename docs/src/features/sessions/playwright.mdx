Notte sessions expose a Chrome DevTools Protocol (CDP) endpoint that you can connect to with Playwright. This allows you to use Playwright's API directly while still benefiting from Notte's cloud infrastructure, anti-detection features, and session management.

## Connection URLs and recordings

| URL | Purpose | Client |
|-----|---------|--------|
| `cdp_url` | Control the live browser over Chrome DevTools Protocol | Playwright `chromium.connect_over_cdp()` (Python), `chromium.connectOverCDP()` (Node), or Puppeteer |
| `playwright_url` | Control the live browser over Playwright protocol, when the server supports it | Playwright `chromium.connect()` |
| `viewer_url` | Open the live browser viewer; interaction depends on the link's permissions | Your web browser |
| Replay `mp4_url` | Watch a recording after the session; does not control a browser | A video player |

`playwright_url` is optional and defaults to `None` in Python. In a server response it can be absent or `null`.
The field prepares the SDK contract for servers that offer Playwright-protocol access; it does not enable that endpoint.
When your server supplies a URL, use the Playwright client version supported by that server.
The CDP examples below and the SDK's page helper continue to use CDP.

With CDP, Playwright runs the browser-action logic on your machine and exchanges CDP commands with the remote browser.
With Playwright protocol, that logic runs beside the browser, which can reduce network round trips for actions such as clicks and fills.
The benefit depends on your network latency and workload; website loading and data transfer still take time.
Use the Sessions API or the SDK's session context manager to stop the session when your automation finishes.

## Prerequisites

Install Playwright alongside the Notte SDK:

```bash
pip install notte-sdk playwright
```

## When to Use Playwright with Notte

Use Playwright directly when you need:

- **Network interception**: Block resources, modify requests/responses
- **Advanced event monitoring**: Console logs, network events, page errors
- **Multiple pages**: Drive several tabs of the same session in parallel
- **Playwright's testing utilities**: Screenshots with full-page scrolling, PDF generation, etc.

For most automation tasks, `session.page` (which is already Playwright-compatible) is sufficient.

## Migrating from Selenium

Notte sessions are driven over CDP, so Playwright (or `session.page`, which is already a Playwright page) is the recommended way to port existing Selenium scripts. Here is a quick comparison:

| Selenium | Playwright (Notte) |
|----------|-------------------|
| `driver.get(url)` | `page.goto(url)` |
| `driver.find_element(By.CSS_SELECTOR, "button")` | `page.locator("button")` |
| `element.click()` | `page.click("button")` |
| `element.send_keys("text")` | `page.fill("input", "text")` |
| `driver.execute_script("...")` | `page.evaluate("...")` |
| `WebDriverWait(driver, 10).until(...)` | `page.wait_for_selector("...")` |
| `driver.save_screenshot("path")` | `page.screenshot(path="path")` |
