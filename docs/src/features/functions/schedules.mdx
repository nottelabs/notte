Schedule a Function to run automatically, for example to collect data every morning or check a page every hour. Each scheduled run executes the latest version of the Function with the variables you saved on the schedule.

A Function has at most one schedule. You can manage it from the **Schedule** tab of the Function in the [Notte Console](https://console.notte.cc), over HTTP, or with the TypeScript SDK. The Python SDK has no schedule methods yet, so call the HTTP API from Python.

## Cron Expressions

Schedules use the AWS EventBridge cron format: **six** space-separated fields, minutes first. This is not the five-field Unix crontab format.

`minutes hours day-of-month month day-of-week year`

- Exactly one of `day-of-month` and `day-of-week` must be `?`; the other must be a real value.
- Schedules fire in UTC.
- `rate(...)` expressions such as `rate(1 hour)` are also accepted.

| Schedule | Expression |
|----------|------------|
| Every day at 9:00 UTC | `0 9 ? * * *` |
| Every hour | `0 * ? * * *` |
| Every 15 minutes | `0/15 * ? * * *` |
| Every Monday at 8:00 UTC | `0 8 ? * MON *` |
| Weekdays at 18:00 UTC | `0 18 ? * MON-FRI *` |
| First day of the month at midnight UTC | `0 0 1 * ? *` |
| Every hour (rate) | `rate(1 hour)` |

A five-field expression such as `0 9 * * *` is rejected.

## Variables

Every scheduled run receives the same `variables`. They must supply every parameter of `run()` that has no default value, and must not include names that `run()` does not declare. A Function without parameters can use an empty object.

## Check a Schedule

The Function's metadata (`GET /functions/{function_id}`, or `fn.get()` in TypeScript) includes:

- `schedule_cron`: the expression, or `null` when the Function is not scheduled
- `schedule_variables`: the variables passed to each scheduled run
- `schedule_state`: `enabled`, `paused`, or `null` when there is no schedule

The example above reads these fields after setting the schedule.

Scheduled runs appear in the Function's run history like any other run. See [Function Management](/features/functions/management#monitoring-executions).

## Paused Schedules

Notte pauses a schedule when its runs cannot succeed without your intervention, for example when your workspace runs out of credit or the Function is no longer active. A paused schedule keeps its expression and variables but stops firing, and `schedule_state` becomes `paused`.

To resume it, fix the cause and set the schedule again with the same request as above.

## Delete a Schedule

Deleting the schedule stops future runs. The Function itself is unchanged and can still be invoked manually.

The example above deletes the schedule in `finally`, including when a metadata request fails.

## Best Practices

- Match the frequency to how often the data actually changes; every run uses browser time and credits.
- Make runs idempotent so a repeated or overlapping run does no harm.
- Return structured results and raise on failure, so failed scheduled runs show up as `failed` in the run history.
