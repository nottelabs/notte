Start with the managed browser defaults described in [Stealth Mode](/features/sessions/stealth-mode). Change one setting at a time and compare the result with a fresh session.

## Diagnose the failure

| Symptom | Next step |
|---------|-----------|
| Site rejects the connection or serves a location-specific page | Check the proxy country and exit IP in [Proxies](/features/sessions/proxies). |
| A CAPTCHA blocks progress | Check [CAPTCHA Solving](/features/sessions/captcha-solving) for supported challenges and waiting behavior. |
| Login or verification keeps repeating | Reuse a consistent identity and [browser profile](/features/sessions/browser-profiles). Check whether credentials or saved login state have expired. |
| A site still detects the browser | Check the recording and compare a fresh session with the defaults. If your workspace has approval, try `advanced_stealth=True`. |
| A request is rate limited | Reduce concurrency and respect the site's retry instructions. A different fingerprint does not resolve account or service limits. |

## Keep the fingerprint consistent

Notte supplies a coherent browser fingerprint. Keep the generated user agent unless your target requires an override. Match proxy location to the workflow, and avoid changing the identity or proxy during a logged-in flow.

## Compare runs

Record the target URL, session ID, observed failure, and the single setting you changed. Use [Recordings](/features/sessions/recordings) to compare successful and failed runs before adding more configuration.
