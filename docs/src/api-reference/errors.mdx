The API uses standard HTTP status codes and returns structured error responses.

## HTTP status codes

| Status | Description |
|--------|-------------|
| `200` | Success |
| `401` | Authentication failed (invalid or missing API key, or an expired or revoked access token), or your plan's credits are exhausted |
| `403` | Forbidden, for example a route that does not accept [access tokens](/concepts/access-tokens#where-tokens-work) |
| `422` | Validation error - malformed request or invalid parameters |
| `429` | Rate limit exceeded, or too many active sessions, agents, vaults, or personas for your plan |
| `500` | Internal server error |
| `529` | Cluster overloaded - no browser capacity available. Includes a `Retry-After` header |

## Error response format

Most errors raised by the API share this envelope. `detail`, `error`, and `message` carry the same text:

```json
{
  "detail": "Description of what went wrong",
  "session_id": "the session involved, or null",
  "status": 401,
  "error": "Description of what went wrong",
  "message": "Description of what went wrong"
}
```

These responses also include an `X-Error-Class` header naming the error type, for example `NotteApiInvalidApiKeyError` or `NotteApiRateLimitExceededError`. Use the status code and this header rather than parsing the message text.

## Common errors

### Authentication (401)

Header `X-Error-Class: NotteApiInvalidApiKeyError`:

```json
{
  "detail": "Unauthorized. Invalid API key.",
  "session_id": null,
  "status": 401,
  "error": "Unauthorized. Invalid API key.",
  "message": "Unauthorized. Invalid API key."
}
```

### Access tokens (401, 403)

Requests made with an [access token](/concepts/access-tokens) can fail with one of these classes, in the standard envelope:

| `X-Error-Class` | Status | `detail` |
|---|---|---|
| `NotteApiAccessTokenExpiredError` | `401` | `access token expired at <time>; mint a new one` |
| `NotteApiAccessTokenInvalidError` | `401` | `invalid or revoked access token` |
| `NotteApiAccessTokenNotAllowedError` | `403` | `access tokens are not accepted on this route; use an API key` |

Header `X-Error-Class: NotteApiAccessTokenNotAllowedError`:

```json
{
  "detail": "access tokens are not accepted on this route; use an API key",
  "session_id": null,
  "status": 403,
  "error": "access tokens are not accepted on this route; use an API key",
  "message": "access tokens are not accepted on this route; use an API key"
}
```

On a `401`, mint a new token. On a `403`, the route needs an API key.

### Validation (422)

Request validation errors use a different envelope, with the individual errors summarized in `message`:

```json
{
  "status_code": 10422,
  "message": "1 validation error: {'type': 'missing', 'loc': ('body', 'url'), 'msg': 'Field required'}",
  "data": null
}
```

### Cluster overloaded (529)

Returned when no browser is available to start a session. Wait for the number of seconds in the `Retry-After` header, then retry.

```json
{
  "error": "Cluster is under heavy load. Please try again in a few minutes.",
  "detail": "Cluster is under heavy load. Please try again in a few minutes."
}
```

### Execution errors

Returned with status `500` when an operation fails. Includes the `X-Error-Class: NotteApiExecutionError` header and the standard envelope.
