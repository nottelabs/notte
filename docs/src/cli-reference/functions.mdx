List, create, and operate on functions.

## `notte functions configure`

Update a function's metadata.

Pass any of `--name`, `--description`, `--domain`, `--run-instructions`, `--default-runtime`, `--response-format`, `--self-healing`, or `--shared`. Only the flags you pass are sent; omitted fields are left unchanged.

`--shared` enables a public code/fork link; `--shared`=false disables it. Code literals become public. Runs, results and runtime secrets stay private. This does not enable public execution.

`--run-instructions` is documentation for whoever calls the function - how long a run takes, what each variable is for, which sites it trips over. It is not input to the self-healing agent.

`--default-runtime` is the runtime every run of this function uses unless that run passes `functions run --runtime`.

`--response-format` is the JSON Schema of what run() returns (inline JSON, @file, or - for stdin).

| Flag | Description |
| - | - |
| `--default-runtime <string>` | Runtime this function's runs use unless a run overrides it: standard or extended |
| `--description <string>` | description |
| `--domain <string>` | domain |
| `--function-id <string>` | Function ID (uses current function if not specified) |
| `--name <string>` | name |
| `--response-format <string>` | JSON Schema of run()'s return value, computed by the caller from its pydantic model, as inline JSON, @file, or - for stdin |
| `--run-instructions <string>` | Notes for whoever calls this function: how long a run takes, what the variables mean, what it trips over |
| `--self-healing` | Let an agent repair the function when a run fails |
| `--shared` | Enable or disable public code sharing and forking for this function. Source code, including embedded credentials, becomes public. Runs, results and stored runtime secrets remain private. This does not enable public execution. Omit or send null to leave sharing unchanged. |

## `notte functions run`

Start the function, print its run ID, and poll until it finishes. Use `--no-wait` to return after startup, then run-metadata `--wait` to wait separately. `--timeout` limits each API request, not the total execution time. Interrupting the CLI does not stop the function; use run-stop to cancel it.

| Flag | Description |
| - | - |
| `--function-id <string>` | Function ID (uses current function if not specified) |
| `--no-stream` | Suppress log output while waiting for the final run metadata |
| `--no-wait` | Return the run ID after startup without waiting for completion |
| `--runtime <string>` | Run on standard or extended for this run only, overriding the function's default-runtime |
| `--var <stringArray>` | Variable as key=value pair (can be used multiple times) |
| `--vars <string>` | Variables as JSON object string |
| `--wait-timeout <duration>` | Maximum time to wait for completion (e.g. 30m; 0 waits indefinitely) |

## `notte functions schedule`

Set a cron schedule for the function

| Flag | Description |
| - | - |
| `--cron <minutes hours day-of-month month day-of-week year>` | AWS EventBridge schedule expression. Six space-separated fields, minutes first: minutes hours day-of-month month day-of-week year. This is neither five-field Unix crontab nor the seconds-first six-field dialect used by Quartz and cron-parser. Exactly one of day-of-month and day-of-week must be `?`, the other must be a real value. Schedules fire in UTC. Example: `0 12 ? * * *` runs daily at noon UTC. `rate(...)` expressions such as `rate(1 hour)` are accepted too. Required. |
| `--function-id <string>` | Function ID (uses current function if not specified) |
