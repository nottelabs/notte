An access token is a short-lived credential that you mint from an API key. Give it to an agent, a sandbox or any other process you trust less than your own code, instead of your API key.

A token acts as the API key it was minted from. It expires after at most one hour, and you can revoke it at any time without touching the key. Its [scope](#scopes) decides which routes it can call: `full`, the default, or `restricted` to browser sessions, page actions, session files, search, scrape and usage.

| | API key | Full access token | Restricted access token |
|---|---|---|---|
| Looks like | `sk-notte-...` | `nat_...` | `nat_...` |
| Lifetime | Until you delete it | 60 seconds to 1 hour, 15 minutes by default | 60 seconds to 1 hour, 15 minutes by default |
| Routes | All | [All but token and admin routes](#full) | [Sessions, page actions, session files, search, scrape, usage and health](#restricted) |
| Can mint or revoke tokens | Yes | No | No |

## How it works

1. Your code keeps the API key and mints a token with `POST /access-tokens`.
2. You pass only the token to the agent or sandbox, for example as its `NOTTE_API_KEY` environment variable.
3. The agent sends the token as a bearer token, exactly like an API key.
4. If the work runs longer than the token's lifetime, your code mints a new one. Tokens cannot be refreshed or extended.
5. When the work is done, your code revokes the token and stops the sessions it started.

If the token leaks, it stops working on its own when it expires, and it cannot be used to mint more tokens. A restricted token also cannot be used to read your API key; a full token can, through a function run (see [Choose a scope](#choose-a-scope)).

## Mint a token

Mint a token with your API key:

<CodeGroup>

```bash cURL
curl -X POST https://api.notte.cc/access-tokens \
  -H "Authorization: Bearer $NOTTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"expires_in": 900, "label": "sandbox-42", "scope": "restricted"}'
```

```http HTTP
POST https://api.notte.cc/access-tokens
Authorization: Bearer sk-notte-...
Content-Type: application/json

{
  "expires_in": 900,
  "label": "sandbox-42",
  "scope": "restricted"
}
```

</CodeGroup>

<ParamField body="expires_in" type="integer" default="900">
  Lifetime in seconds, from `60` to `3600`.
</ParamField>

<ParamField body="label" type="string">
  Optional free text of up to 128 characters, for example the id of the sandbox that receives the token.
</ParamField>

<ParamField body="scope" type="string" default="full">
  `full` or `restricted`. See [Scopes](#scopes). Any other value answers `422`.
</ParamField>

The body is optional. Without one, the token lives 15 minutes, has no label and has full access.

The API answers `201 Created`:

```json
{
  "id": "<token id>",
  "token": "nat_...",
  "expires_at": "2026-11-12T21:15:00Z",
  "label": "sandbox-42",
  "scope": "restricted"
}
```

<Warning>
  The `token` value is shown only in this response. Notte stores a hash of it, never the token itself, so it cannot be shown again. Keep the `id`: you need it to revoke the token.
</Warning>

Only an API key can mint tokens. An API key can have up to 50 active tokens at once; minting more answers `409`. Minting is also rate limited per API key, and answers `429` when you go over the limit.

## Use a token

Send the token in the `Authorization` header, the same way as an API key:

```bash
curl -X POST https://api.notte.cc/sessions/start \
  -H "Authorization: Bearer $NOTTE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```

On the routes its scope allows, the request runs as the parent API key: the same workspace, plan, usage and rate limits.

## Revoke a token

Revoke a token with the API key that minted it:

<CodeGroup>

```bash cURL
curl -X DELETE https://api.notte.cc/access-tokens/$TOKEN_ID \
  -H "Authorization: Bearer $NOTTE_API_KEY"
```

```http HTTP
DELETE https://api.notte.cc/access-tokens/{id}
Authorization: Bearer sk-notte-...
```

</CodeGroup>

The API answers `204 No Content`. Revoking is idempotent: revoking a token that is already revoked also answers `204`. Another API key gets `404`, and a token cannot revoke tokens.

A revoked token stops working within seconds. Deleting the parent API key, or removing the key's owner from the workspace, stops its tokens within 60 seconds.

## Scopes

### Full

A full token, the default, acts as its API key on every route the key can call, except:

- minting and revoking tokens (`POST /access-tokens`, `DELETE /access-tokens/{token_id}`), which answer `403` with `NotteApiAccessTokenNotAllowedError`;
- admin routes, which take an API key only.

Function runs work with a full token, with one exception today:

- Start a run with `POST /functions/{function_id}/runs/start`, sending the token in both the `Authorization` and the `x-notte-api-key` headers.
- Starting an existing run by its id (`POST /functions/{function_id}/runs/{run_id}`), which the SDK's `function.run()` uses, answers `400` to every access token. Use an API key there.

### Restricted

A restricted token works on these routes, and nowhere else:

| Area | Routes |
|---|---|
| Sessions | `POST /sessions/start`<br />`GET /sessions`<br />`GET /sessions/{session_id}`<br />`DELETE /sessions/{session_id}/stop` |
| Page actions | `POST /sessions/{session_id}/page/observe`<br />`POST /sessions/{session_id}/page/execute`<br />`POST /sessions/{session_id}/page/scrape`<br />`POST /sessions/{session_id}/page/screenshot` |
| Session debug, replay and network logs | `GET /sessions/{session_id}/debug`<br />`GET /sessions/{session_id}/offset`<br />`GET /sessions/{session_id}/network/logs`<br />`GET /sessions/{session_id}/replay` |
| Session files | `GET /sessions/{session_id}/files`<br />`POST /sessions/{session_id}/files`<br />`GET /sessions/{session_id}/files/{file_id}` |
| Search and scrape | `POST /search`<br />`POST /scrape` |
| Usage and health | `GET /usage`<br />`GET /health` |

Every other route answers `403` with `NotteApiAccessTokenNotAllowedError` when it receives a restricted token, including minting and revoking tokens, functions and their runs, vaults, personas and profiles. Minting and revoking tokens, and admin routes, take an API key only; for the other routes, use an API key or a full token.

A session started on your own browser (with `cdp_url` in `POST /sessions/start`) keeps that URL from a restricted token: the session routes answer it with `cdp_url: null`, since the URL can carry credentials for your browser provider.

### Choose a scope

A full token can start function runs, and a run's code can read the parent API key. Code that holds a full token can therefore get the key and keep using it after the token expires or is revoked.

- Give a full token only to code you would trust with the API key itself.
- Use `restricted` when the token's expiry and revocation must hold, for example for an agent that only drives a browser.

## Errors

Token errors use the standard [error envelope](/api-reference/errors#error-response-format) and name their error class in the `X-Error-Class` header:

| `X-Error-Class` | Status | When | `detail` |
|---|---|---|---|
| `NotteApiAccessTokenExpiredError` | `401` | The token has expired | `access token expired at <time>; mint a new one` |
| `NotteApiAccessTokenInvalidError` | `401` | The token is unknown or revoked | `invalid or revoked access token` |
| `NotteApiAccessTokenNotAllowedError` | `403` | The route does not accept tokens, or not tokens of this scope | `access tokens are not accepted on this route; use an API key` |

Check the status code and the `X-Error-Class` header rather than the message text. On a `401`, mint a new token. On a `403`, call the route with an API key instead, or with a full token if the route is not a token or admin route.

## Lifetimes and what outlives a token

The token itself lives for `expires_in` seconds, one hour at most, or until you revoke it.

Some routes return other credentials, such as session links and signed download URLs. Those keep their own lifetime: when the token expires or is revoked, they keep working.

| Credential | Returned by | Valid for |
|---|---|---|
| Session CDP, viewer and debug links | `POST /sessions/start`, `GET /sessions/{session_id}`, `GET /sessions/{session_id}/debug` | Until the session ends |
| Signed replay URLs | `GET /sessions/{session_id}/replay` | Up to 1 hour |
| Signed network log URLs | `GET /sessions/{session_id}/network/logs` | Up to 1 hour |
| File download links | `GET /sessions/{session_id}/files/{file_id}` | 5 minutes |

<Warning>
  Whoever holds a session's CDP link controls its browser: they can read the session's cookies and any secret the session fills in. Stopping the session cuts off its CDP, viewer and debug links. When you revoke a token, also stop the sessions it started.
</Warning>

## Manage tokens in the console

In the [Notte Console](https://console.notte.cc), open **Settings → Access tokens** to:

- create a token: choose a name, the API key it acts as, a lifetime of up to one hour and its access, **Full access** (the default) or **Restricted**. The console shows the token once.
- list tokens, filtered by status: active, expired or revoked. The **Access** column shows each token's scope.
- revoke a token.
