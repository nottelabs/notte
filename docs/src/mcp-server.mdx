Notte Browser MCP gives your AI assistant cloud browsers for navigating websites, interacting with pages, extracting data, and reusing saved logins. Browser sessions consume credits while active, so stop them when your task is finished.

## Connect Notte Browser MCP

Connect your client to the hosted MCP endpoint:

```text
https://api.notte.cc/mcp
```

Clients that support OAuth can prompt you to sign in with your Notte account and choose a workspace. For clients or scripts that use bearer authentication, create a [Notte API key](https://console.notte.cc/apikeys).

<Tabs>
  <Tab title="Claude Code" icon="/images/claude-logo.svg">
    Add the server, then run `/mcp` in Claude Code and authenticate with your Notte account:

    ```bash
    claude mcp add --transport http notte https://api.notte.cc/mcp
    ```

    If you prefer an API key, add the header explicitly:

    ```bash
    claude mcp add --transport http notte https://api.notte.cc/mcp --header "Authorization: Bearer $NOTTE_API_KEY"
    ```
  </Tab>
  <Tab title="Codex" icon="/images/openai-logo.svg">

    ```toml
    [mcp_servers.notte]
    url = "https://api.notte.cc/mcp"
    bearer_token_env_var = "NOTTE_API_KEY"
    ```
  </Tab>
  <Tab title="Cursor" icon="/images/cursor-logo.svg">
    Open your MCP settings and add:

    ```json
    {
      "mcpServers": {
        "notte": {
          "url": "https://api.notte.cc/mcp",

            "Authorization": "Bearer ${env:NOTTE_API_KEY}"
          }
        }

    }
    ```
  </Tab>

  </Tab>
  <Tab title="Others" icon="/images/mcp-logo.svg">

## Browser tools

The browser workflow is `manage_browsers(start)` → `browser_action(goto)` → `browser_observe` → act and observe again → `manage_browsers(stop)`.

The three page-reading tools are read-only. Management tools group inspection with state-changing actions and are marked as write tools, so your client may request confirmation even for their list or get actions.

| Tool | Permission hint | Actions or purpose |
| --- | --- | --- |
| `manage_browsers` | Write | `start`, `list`, `status`, `stop` |
| `browser_observe` | Read | Read page state, tabs, and available element IDs |
| `browser_scrape` | Read | Extract page markdown or structured data |
| `browser_screenshot` | Read | Capture the current viewport |
| `browser_action` | Write | Navigate, click, fill forms, and interact with pages |
| `manage_files` | Write | `upload`, `list_uploads`, `get_upload`, `list_downloads`, `get_download` |
| `manage_profiles` | Write | `create`, `list`, `get`, `duplicate`, `delete` |
| `manage_auth` | Write | `list`, `get`, `check`, `reauthenticate` |

To save a login, create a profile with `manage_profiles`, then start a browser with both `profile_id` and `persist_profile=true`. Stop the browser to save its state; before reusing it, check `persisted_domains` with `manage_profiles(action="get")`.

## Verify the connection

Run this prompt in your assistant:

```text
Use Notte Browser MCP to start a browser, navigate to https://example.com, observe the page, and extract its heading as structured JSON. Report the result and stop the browser when finished, including if any step fails.
```

## Other Notte MCP endpoints

For the broader developer API, including function and agent administration, use `https://api.notte.cc/mcp/full`. It accepts the same OAuth sign-in or Notte API key. The browser connector at `/mcp` does not expose those administration tools.

[Anything API](https://anything.notte.cc) has its own MCP endpoint at `https://anything.notte.cc/mcp` for finding, running, and building reusable APIs.

## Notte Documentation MCP

You can also configure the Notte Docs MCP to give your coding agent current documentation while it helps you build. It needs no API key.

```text
https://docs.notte.cc/mcp
```
